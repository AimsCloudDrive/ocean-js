1需求背景与目标

model-designer 是当前项目的子项目，用于以图形化方式编辑和维护业务模型（可类比数据库表结构建模工具）。当前模型数据存储在 MongoDB 中，但缺少可视化的编辑界面，新增、调整模型与模型关系都需要直接操作数据，效率低且容易出错。

本期目标：实现一个基于 Canvas 的模型设计器，支持模型的创建、编辑、拖动、框选，模型间关系的建立与查看，以及画布的缩放与平移。前端通过后端接口文档定义的接口加载和操作 MongoDB 元数据。本期范围

前端不使用 IndexedDB 或其它浏览器本地数据库保存设计数据。页面初始化通过 GET /api/model-designer/bootstrap 加载数据；模型和关系除位置改变外均立即调用接口更新，位置变化在拖动结束或点击同步位置按钮时提交。

设计原则

  • 画布内所有元素（背景网格、模型、关系线、信息框）一律由 Canvas 2D 绘制，不使用 DOM 元素拼装。
  • 交互优先：创建、拖动、框选、查看均通过画布直接操作完成，属性编辑通过抽屉面板辅助。
  • 模型单点拖动严格对齐格点（落点吸附）；框选拖动自由移动；数据层位置统一保存自由坐标；所有可移动元素均受锁机制约束。

3整体界面与布局

界面由四部分组成：顶部左上角工具区（模式切换、同步位置、删除）、左侧功能区（创建按钮组）、中央画布（Canvas，占满剩余区域）、右侧抽屉（点击模型后滑出，默认隐藏）。

整体布局：左上角工具区 + 左侧创建按钮组 + 中央画布（5 格一档加粗网格）+ 右侧抽屉

布局规则

  • 左上角工具区：模式切换（只读 / 编辑）、同步位置按钮；删除按钮在存在激活（选中）模型或关系时显示。同步位置按钮只提交画布、模型和关系的位置变化。
  • 左侧功能区：竖向按钮组，三个独立按钮：创建模型创建关系继承关系。
  • 画布占据左侧工具栏与顶部工具区之外的整个区域，随窗口大小自适应。
  • 抽屉在点击模型时从右侧滑出，宽度固定（如 320px）；再次点击其他模型切换选中对象，点击画布空白处关闭。

4画布、网格与视图操作

4.1 网格背景

画布背景为横竖方格线，采用每 5 格加粗一个等级的规则，最多 3 级：

级别格子边长线型用途
第 1 级基础格（16px）细线（浅色）普通格点，模型单点拖动吸附的最小单位
第 2 级5 个基础格（80px）加粗中线次级参考线
第 3 级25 个基础格（400px）最粗线画布级参考线，全图最多 3 级
注意：最小格不能设置过小，否则拖动模型时频繁跳动、难以对准，产生"跳跃感"。基础格边长取 16px。

4.2 缩放与平移

操作交互参数
缩放滚动滚轮，以鼠标位置为锚点范围 0.5× ~ 2×，步进 0.1×
平移拖拽画布空白区域不触发模型/关系拖动；与框选以拖拽起点区分
  • 缩放与平移仅改变视图，不影响模型坐标的存储语义。
  • 网格线随缩放同步变化，加粗层级按当前缩放后的格距自动适配（缩放后仍保持 5 格一档）。

5模型（节点）

模型节点：圆形 + 主色边框 + 居中名称；选中时出现矩形包围盒，其左上角显示锁图标

5.1 状态

状态触发表现
常规默认 / 取消选中仅显示圆形节点
激活（选中）点击打开抽屉、hover 悬停、框选命中显示矩形包围盒与左上角锁图标；存在激活对象（模型或关系）时左上角显示删除按钮

5.2 自身属性

属性说明编辑规则
模型 ID模型唯一标识，即数据库集合名（每个模型对应一个集合），创建时生成编辑模式下可编辑（即重命名集合），只读模式不可改
名称模型显示名称，画布节点中央展示编辑模式可改
描述模型用途说明，纯文本编辑模式可改
颜色节点边框主色，色板选择编辑模式可改
继承模型 IDparentModelId，标注本模型继承自哪个模型，为空表示无继承；父模型元数据同步记录本模型 ID 至 childModelIds编辑模式可改；查询模型信息时按此 ID 递归查询父模型获取继承字段
画布位置隐性属性，节点坐标 (x, y)，由拖动产生不可直接编辑；坐标从来都保存自由坐标——单点拖动吸附格点后，保存的仍是该格点处的自由坐标值（如 x: 64.0），不存在格点索引存储

5.3 字段属性

  • 字段列表分两部分展示：继承字段在前、本模型字段在后；继承字段由 parentModelId 递归查询父模型得到。
  • 继承字段不参与排序，无排序手柄、不可编辑（名称、类型、描述只读），仅可展开查看描述。
  • 本模型字段支持新增、修改、删除、排序（拖拽排序手柄调整顺序）。
  • 列表上方提供显隐图标，控制是否显示继承字段（切换继承字段区展开/收起）；该显隐状态变化后立即通过模型更新接口提交，首次进入默认显示。规则
  • 行结构：行首折叠按钮 → 字段名 → 字段类型；点击折叠按钮在该行下方展开显示字段描述。
字段类型建议覆盖：String、Number、Boolean、Date、ObjectId（引用其他模型）、Array<T>、Object。建议

6关系（连线）

6.1 两种形态

形态默认 / 触发表现
直连（默认）关系创建后的初始状态信息框位于两模型中间，两根直线箭头分别指向两端模型
曲线信息框被拖动后变为三点贝塞尔曲线，且关系自动锁定，位置不再变动

6.2 箭头与模型保持距离

  • 箭头不能挨着模型：线段在靠近模型边缘处截断，距模型留出固定间距（12px），该段不绘制，避免箭头压住节点。规则

6.3 一体信息框

  • 信息框是一体的：一个框内同时显示两个方向的信息（如 A→B 名称·映射 与 B→A 名称·映射）。
  • 信息框的拖动与点击均为整体同步：拖动任一部分即拖动整个框；点击框内任意位置视为点击该关系。
  • 直连态下信息框默认居中于两模型连线上。

6.4 映射规则（1 / m / n）

取值含义示例
1该方向一个模型至多关联对方 1 个（1:1 或多:1 的一侧）A→B 显示 1
m该方向一个模型可关联对方多个（多对多时的一侧）A→B 显示 m
n另一个方向一个模型可关联对方多个（多对多时的另一侧）B→A 显示 n
  • 两侧独立取值：多对多时一侧显示 m、另一侧显示 n。
  • 映射值可点击关系后在抽屉中修改（见 6.6）。

6.5 关系命名

  • 创建时默认：A→B 方向的关系名称 = B 的模型 ID，B→A 方向 = A 的模型 ID。
  • 名称可在抽屉中修改。

6.6 点击关系查看与编辑

点击关系（曲线、直线或信息框）弹出抽屉，这一对关系的两个方向都显示：各自的关系名称与映射，均可在编辑模式下修改。

6.7 继承关系

  • 以灰色虚线箭头表示，方向为子模型指向父模型。
  • 继承关系不可拖动、没有信息框，不参与映射。
  • 其语义与模型元数据 parentModelId / childModelIds 对应。

7锁定与拖动规则

7.1 锁机制

核心规则：模型与关系的矩形区域左上角都有一把锁图标。一旦被拖动（含框选整体拖动），即自动锁定，位置不可再变动；点击锁图标解锁后，才恢复可拖动。
元素拖动触发锁定表现解锁行为
模型拖动节点本体、框选整体拖动位置固定，不可再拖动恢复可拖动，位置保持解锁前
关系拖动信息框曲线形态固定，不可再拖动恢复默认直连状态（信息框回中间、直线箭头），可再次拖动

7.2 模型拖动与吸附

  • 模型（解锁状态下）单点拖动，松手后吸附到最近格点作为最终落点。
  • 拖动过程中实时吸附，基础格 16px 保证不产生跳跃感。
  • 吸附仅影响落点位置；数据层坐标始终以自由坐标保存，吸附后即该格点的坐标值（如 (64.0, 112.0)），不保存格点索引。
  • 模型位置变化后，相连关系的曲线自动重算（保持锁定状态与信息框相对位置）。

7.3 关系拖动与绘制

  • 关系只可拖动信息框，曲线/直线本身不可拖动；拖动信息框后关系切换为曲线形态并锁定。
  • 曲线由三个锚点生成：源模型中心 → 信息框中心 → 目标模型中心，绘制为平滑贝塞尔曲线。
  • 曲线穿过信息框背后的一段不绘制（信息框遮挡曲线）；箭头端按 6.2 规则与模型保持间距。

7.4 框选拖动

  • 框选命中的内容支持整体拖动：拖动任意选中模型即可整体移动所有选中对象。
  • 框选拖动为自由移动、不吸附格点，松手后保持当前位置。
  • 框选拖动后同样触发锁定：命中对象均自动置锁。规则

8创建操作流程

操作前置状态交互过程结果
创建模型 点击左侧"创建模型"，进入创建态 点击画布任意位置，系统取距点击点最近的格点作为新模型位置 在该格点生成新模型，自动弹出抽屉可立即编辑
创建普通关系 点击左侧"创建关系"，进入创建态 先点击源模型，再移动到目标模型上完成 生成双向关系，默认直连形态，按默认规则命名并计算映射
创建继承关系 点击左侧"继承关系"，进入创建态（与"创建关系"为两个独立按钮） 点击子模型，再点击父模型 生成灰色虚线箭头（子 → 父），无信息框；子模型元数据写入 parentModelId，父模型元数据同步写入子模型 ID 至 childModelIds
  • 创建态下点击画布空白处取消创建；创建态激活时画布出现对应提示（光标样式变化）。
  • 仅编辑模式下可执行创建类操作。
  • 删除继承关系（或修改 parentModelId）时，同时从父模型 childModelIds 中移除对应子模型 ID，保持双向一致。
  • 创建继承关系前必须检查是否成环：若目标父模型已经是该子模型的直接或间接后代（沿 childModelIds 递归可达），则拒绝创建并提示。规则

9模式、接口同步与删除

9.1 模式切换

  • 只读 / 编辑切换按钮位于左上角。
  • 编辑模式：全部操作可用（创建、拖动、编辑、删除、同步位置）。
  • 只读模式：仅可查看与打开抽屉（只读展示），创建、拖动、编辑、删除、同步位置均禁用。

9.2 接口同步

  • 页面初始化调用 GET /api/model-designer/bootstrap，一次性加载画布基础元数据、模型元数据和关系元数据。
  • 模型和关系除位置改变外，创建、编辑、锁定、解锁、继承字段显隐及删除操作均立即调用接口更新。
  • 模型、关系和画布的位置变化在拖动结束后调用对应接口提交；左上角同步位置按钮可统一重试尚未成功提交的位置变化。
  • 接口请求期间显示操作中状态；请求失败时回滚到最近一次服务端状态或保留当前界面并提供重试，不写入 IndexedDB。

9.3 删除模型（递归规则）

核心规则：删除模型前先检查是否有继承它的子模型（通过 childModelIds）；有子模型时，须确认子模型已被选中（框选命中）才能删除，否则拒绝本次删除；子模型选中则先递归删除子模型，再删除该模型。
  • 递归判断：对每个子模型重复上述检查（其自身是否有继承它的后代），直至所有后代可删或被拒绝。
  • 删除模型的同时，删除与其关联的全部关系（普通关系与继承关系），并同步清理相关模型元数据（父/子 ID 引用）。

9.4 删除关系

  • 关系可直接删除，无继承检查、无级联逻辑。
  • 删除入口与模型一致：使用左上角删除按钮——选中（激活）模型或关系时按钮可用，点击删除当前激活对象。规则

10框选

10.1 命中规则

  • 框选同时包含模型与关系：模型与矩形框相交即选中；关系的连线（或信息框）与矩形框相交即选中。规则
  • 框选命中后，模型显示包围盒与锁图标，关系高亮显示。

10.2 框选拖动

  • 框选命中的内容支持整体拖动，拖动过程中任意移动、不吸附格点。
  • 框选拖动后命中对象自动锁定（同 7.4）。

10.3 框选删除

规则：框选删除时，关系不按框选直接判定删除，按如下两步处理：① 排除——关系两端中任一端属于选中（被删）模型集合的，排除不处理（删除模型时会自动删除其关联关系，避免重复）；② 单独删除——剩下的、与选择框相交且两端都不属于选中模型集合的关系，单独删除。
  • 模型删除按 9.3 递归规则执行；被删模型的所有关联关系随模型删除自动清理。
  • 框选删除同样受继承递归规则约束（有未被选中的子模型时拒绝删除父模型）。

11数据约定（MongoDB 正式格式）

每个模型对应一个集合，集合内只保存该模型的真实数据文档；所有元数据统一存放在特殊集合 __META__ 中。真实数据文档通过 uuid 与关系元数据中的 related 关联。

11.1 真实数据集合（每个模型一个，集合名 = 模型 ID）

// 集合：user（集合名即模型 ID）
{
  "uuid": "8f2a9c1e-4b3d-...",   // 真实数据文档必有的 uuid，系统自动生成
  "username": "zhangsan",        // 业务字段
  "age": 28
}

11.2 __META__ 集合：基础元数据文档（仅一个）

{
  "META_TYPE": "base",           // 元数据类型：base
  "center": { "x": 0, "y": 0 },  // 画布中心坐标
  "scale": 1                     // 缩放大小
}

11.3 __META__ 集合：模型元数据文档（每个模型一个）

{
  "META_TYPE": "model",          // 元数据类型：model
  "model": {                     // 模型基础信息
    "id": "user",                // 模型 ID（对应集合名，编辑模式下可修改即重命名集合）
    "name": "用户",
    "description": "平台注册用户",
    "color": "#2563eb",
    "locked": false,
    "parentModelId": null,       // 继承来源模型 ID
    "childModelIds": []          // 继承该模型的子模型 ID 列表
  },
  "fields": [                    // 字段信息（仅本模型自有字段）
    { "name": "username", "type": "String", "description": "登录名" }
  ],
  "position": { "x": 68.5, "y": 112 }   // 位置信息（自由坐标）
}

11.4 __META__ 集合：普通关系元数据文档（每个普通关系一个）

{
  "META_TYPE": "relation",       // 元数据类型：relation
  "relationship": {              // 关系信息：一个对象，两个键即双向关系名
    "订单ID": {                  // 该方向关系名（默认 = 指向模型 ID）
      "source": "user",          // 源模型
      "target": "order",         // 指向模型
      "related": {               // 真实数据文档关联：键 = 源模型文档 uuid，值 = 指向模型文档 uuid 数组（双向均维护）
        "8f2a9c1e-...": ["5d1b3a77-...", "0c9e4f22-..."]
      },
      "mappingType": "1"         // 映射：1 / m / n
    },
    "用户ID": {                  // 另一个方向关系名
      "source": "order",
      "target": "user",
      "related": {               // 反向同样维护：键 = 该方向源模型文档 uuid，值 = 指向模型文档 uuid 数组
        "5d1b3a77-...": ["8f2a9c1e-..."]
      },
      "mappingType": "m"
    }
  },
  "relationType": "relation",    // 关系类型
  "position": { "x": 300.0, "y": 200.0 }   // 信息框中心坐标（自由坐标）
}

11.5 __META__ 集合：继承关系元数据文档（每个继承关系一个）

{
  "META_TYPE": "relation",       // 元数据类型仍为 relation
  "relationType": "inherit",     // 通过关系类型区分：inherit
  "source": "child",             // 源模型（子模型）
  "target": "parent"             // 指向模型（父模型）
}
已确认：关系不保存描述数据（relationship 每方向仅含 source / target / related / mappingType）；related 双向均须维护——A→B 方向存源模型文档 uuid 到目标文档 uuid 数组的映射，B→A 方向存反向映射。画布设置和继承字段显隐状态统一通过后端接口保存，不使用浏览器本地数据库。
